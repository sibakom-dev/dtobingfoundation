For a small-to-medium nonprofit, I would keep the site intentionally lean. The goal is to make it easy for the foundation staff to update without needing a developer. Everything that changes frequently should come from the CMS, while evergreen content remains as Markdown pages.

---

# Project Brief

## Project

Rebuild **The Darius Tobing Foundation** website using:

* **Eleventy (11ty)** for static site generation
* **Sveltia CMS** for content management
* **Nunjucks** templates
* Responsive, accessible design
* Minimal JavaScript
* Optimized for SEO and performance

---

# Goals

The website should communicate:

* Who the foundation is
* What it does
* Its three program pillars
* Upcoming events
* Stories and impact
* How people can help

The CMS should be simple enough for non-technical staff.

# Technical Requirements

* Eleventy v3
* Nunjucks templates
* Sveltia CMS
* Markdown content
* Image optimization (`@11ty/eleventy-img`)
* Responsive images with lazy loading
* Automatic Open Graph image generation (fallback to site default)
* Sitemap generation
* RSS feed for Stories
* Robots.txt
* Canonical URLs
* Schema.org metadata for Organization, Event, and Article
* WCAG AA accessibility
* Lighthouse targets: Performance ≥95, Accessibility ≥95, Best Practices ≥95, SEO ≥95

This scope keeps the site maintainable by using **only four dynamic collections** (Stories, Events, Programs, and Site Settings), while all other content lives in simple Markdown pages. It strikes a good balance between flexibility and ease of content management for a nonprofit with a small editorial team.
